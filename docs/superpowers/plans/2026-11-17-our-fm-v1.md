# Our FM v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A passcode-gated web page where colleagues queue Spotify songs that a cloud server plays, in order, on the office iPhone through the Spotify Web API, with skip votes and a play log.

**Architecture:** One Node 24 ESM process: Express 5 routes over small units (config, SQLite store, Spotify client, pure skip rules, a serialized player state machine, auth middleware). One static page polls `/api/state`. Every unit takes its dependencies as arguments so tests inject fakes.

**Tech Stack:** Node.js 24 (ESM), Express 5 (only dependency), `node:sqlite` `DatabaseSync`, `node:test` + `node:assert/strict`, plain HTML/JS.

**Spec:** `docs/superpowers/specs/2026-11-17-our-fm-v1-design.md`. Read it; it is the source of truth for behaviour. This plan fixes files, names, signatures and tests.

## Global Constraints

- `"type": "module"`, `engines.node` `"24.x"`, dependencies: `express` `^5` only. No dev dependencies.
- Scripts: `start` = `node --disable-warning=ExperimentalWarning src/server.js`; `dev` = `node --disable-warning=ExperimentalWarning --env-file-if-exists=.env src/server.js`; `test` = `node --disable-warning=ExperimentalWarning --test test/`.
- Never commit secrets. `.env.example` has placeholders only. `.gitignore` adds `data/`.
- Never log tokens, auth codes, the passcode, or Authorization headers.
- Constants (in `src/config.js`): `MAX_QUEUED_PER_PERSON = 3`, `SKIP_VOTES = 3`, `SKIP_VOTES_WITH_REQUESTER = 2`, `TICK_MS = 3000`, `START_GRACE_MS = 5000`, `LOOKAHEAD_MS = 3500`.
- `OFFICE_PASSCODE` at least 8 characters.
- Spotify scopes: `user-read-playback-state user-modify-playback-state`.
- Exact UI copy: `Open Spotify on the speaker iPhone`; `Spotify isn't connected yet — owner: open /auth/login`; `Queue is empty — add a song`.
- Times stored as ISO 8601 UTC strings; functions take `now` as epoch ms.
- Error responses are `{ "error": "<message>" }`.
- All UI text goes in via `textContent`; no inline `<script>` (CSP).

## Review Focus

1. **A queued track Spotify refuses to play** (403/400 on `play`, e.g. unavailable in market): the queue must not stall forever. Expected: the item is removed from the queue, status `error` with message `Couldn't play "<title>" — removed from queue`, and the next tick moves on. Test in Task 3 (`play 403 drops the item`).
2. **The iPhone sleeps mid-song** (`getPlayer` returns `null` repeatedly): the song ends after two consecutive misses, the next song waits with `no_device` instead of erroring. Test in Task 3.
3. **Server restart while a song plays**: an open play that Spotify still shows continues untouched; one Spotify no longer shows ends after two misses. Test in Task 3.
4. **Two skip votes and the lookahead timer at the same moment**: exactly one advance, exactly one new play. Test in Task 3.
5. **Song titles or names containing `<script>` / quotes**: the API returns them verbatim as JSON strings and the page renders them as text. Test in Task 4 (`queue item title is returned verbatim`); UI uses `textContent` only (checked in final review).

### Task 2: Spotify client

**Files:**
- Create: `src/spotify.js`
- Test: `test/spotify.test.js`

**Interfaces:**
- Consumes: Store `getSetting/setSetting/deleteSetting` (key `refresh_token`); `Track` shape.
- Produces:
  - `class SpotifyError extends Error { status: number }`; `class NotConnectedError extends Error`; `class RateLimitedError extends Error { retryAfterMs: number }`.
  - `createSpotify({ clientId, clientSecret, redirectUri, store, fetch = globalThis.fetch, now = Date.now }) → Spotify`:
    - `isConnected() → boolean`
    - `authorizeUrl(state) → string` (`https://accounts.spotify.com/authorize?response_type=code&client_id&scope&redirect_uri&state`)
    - `exchangeCode(code) → Promise<void>` (stores `refresh_token`, caches access token)
    - `search(q) → Promise<Track[]>` (`GET /v1/search?type=track&limit=10&market=from_token&q=`)
    - `getTrack(id) → Promise<Track>` (`GET /v1/tracks/{id}?market=from_token`)
    - `getDevices() → Promise<{ id, name, isActive }[]>`
    - `getPlayer() → Promise<null | { trackId: string|null, progressMs: number, isPlaying: boolean, deviceId: string|null }>` (204 → `null`)
    - `play(deviceId, uri)`, `pause(deviceId)`, `transfer(deviceId)` → `Promise<void>` (`PUT /me/player/play?device_id=` body `{uris:[uri]}`; `PUT /me/player/pause?device_id=`; `PUT /me/player` body `{device_ids:[id], play:false}`)
  - Track mapping: `artist` = artist names joined by `', '`; `artistId` = first artist id or `null`; `imageUrl` = `album.images[1]?.url ?? album.images[0]?.url ?? null`.

Behaviour: access token cached until 60 s before expiry. Token endpoint uses `Authorization: Basic base64(id:secret)` and form body. A `refresh_token` in a refresh response replaces the stored one. API 401 → refresh once and retry once. Token response `error: 'invalid_grant'` → `deleteSetting('refresh_token')`, throw `NotConnectedError`. No stored token → `NotConnectedError`. 429 → `RateLimitedError` with `Retry-After` seconds × 1000 (default 5000). Other non-2xx → `SpotifyError` with status and a message naming the endpoint path (never the token).

### Task 3: Player state machine

**Files:**
- Create: `src/player.js`
- Test: `test/player.test.js`

**Interfaces:**
- Consumes: Store (Task 1), `evaluateSkip` (Task 1), Spotify interface + error classes (Task 2), `pick` (Task 1), constants.
- Produces:
  - `class NothingPlayingError extends Error`
  - `createPlayer({ store, spotify, deviceName, autopick, clock = { now: Date.now, setTimeout, clearTimeout, setInterval, clearInterval }, log = console }) → Player`:
    - `tick() → Promise<void>` — serialized through the lock; never rejects.
    - `kick() → void` — fire-and-forget `tick()`.
    - `skip(clientId, name) → Promise<{ votes, needed, skipped: boolean }>` — serialized; rejects `NothingPlayingError`.
    - `getState() → { status, message: string|null, progressMs: number|null, isPlaying: boolean }` — `progressMs` estimated as in the spec.
    - `start()` (interval `TICK_MS`, plus an immediate tick), `stop()` (clears interval and lookahead timer).
  - `status` values: `needs_auth | no_device | idle | playing | paused | error`.

Implement exactly the spec's "Player" and "Skip" sections, plus Review Focus 1: when `play` throws `SpotifyError` with status 400 or 403 (not 404, which takes the transfer-and-retry path), remove that queue item, set status `error` with message `Couldn't play "<title>" — removed from queue`. A `RateLimitedError` sets a back-off until `clock.now() + retryAfterMs`. `NotConnectedError` → `needs_auth`. Misses counter resets when a new play starts.

The lock: `let chain = Promise.resolve(); const locked = fn => (chain = chain.then(fn, fn))` style, with each job's errors caught and logged so the chain never breaks.
