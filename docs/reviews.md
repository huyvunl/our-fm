# Reviewer verdicts

Fresh Sonnet reviewer subagents stood in for the owner at each approval point.

- **Design (brainstorm), round 1: CHANGES.** Accepted: transfer-and-retry on 404 device, least-privilege scopes, `trust proxy`, server-side OAuth state, JSON-only mutating requests, `/auth/login` only while disconnected, per-browser clientId for votes/cap/remove, pause when queue runs dry, restart reconciliation, passcode min length, no token logging. Partly declined: kept the HMAC cookie (3 lines, no extra secret); skip/cap numbers became constants rather than env vars.
- **Spec, round 1: CHANGES.** Accepted: 403 handling, vote counts only if clientId *and* normalized name are new, votes reset per play, passcode ≥ 8 chars, security headers + CSP, two consecutive misses before ending a song, 2 h no-repeat stated as auto-pick only, clientId in a header not the URL, pinned Node 24 + silenced sqlite warning. Declined: owner-id check on `/auth/login` (passcode + only-while-disconnected is enough for trusted colleagues, and avoids another owner step); per-person skip cooldown (multi-person thresholds already meet "one person can't skip everything"); dropping the lookahead timer (avoids up to 3 s silence per song; races covered by the lock + play-id check and tests); estimated progress on normal ends (the required column is progress at skip only). Not re-reviewed: all changes were additive clarifications.
- **Plan, round 1: CHANGES.** All accepted: fake-clock contract (`clock.now()` everywhere, tests drive `tick()`), a concrete race-test recipe, an explicit lock snippet that keeps the chain alive while `skip()` still rejects, `autopick` passed as `{ pick }`, a second play refusal in a row no longer drains the queue (spec updated too), middleware order with static before `requireAuth`, a DEPLOY.md content list, Windows-safe temp cleanup in the smoke test. Not re-reviewed: precise additions, no direction change.
- **Build, final whole-branch code review (Opus): CHANGES.** One Critical: the page's Skip button sent no name, so every skip returned 400. Two Important: a play that never started was logged as played and drained the queue; Spotify calls had no timeout and could stall the player lock. Plus 14 Minor. One fix wave fixed C1, I1, I2 and 11 minors: skip votes now target a play id, the counted vote total is shown, the lookahead is cancelled on pause, a song removed mid-start no longer errors, the page shows "Reconnecting…" and a paused banner, search results no longer re-render, the auto-play seam gets `spotify`, error logs are de-duplicated, the toast auto-hides, and shutdown drains in-flight work. Declined M8 (falling back to the first device is the owner's requirement; DEPLOY.md explains it). Covered M12 in DEPLOY.md (the per-IP login limit is deliberate).
- **Fix wave, scoped re-review (Sonnet): ALL ADDRESSED**, no new Critical/Important breakage. Residual minors: errors raised inside `startNext` still log every tick; a `kick()` that arrives mid-tick waits for the next tick, at most 3 s.

## Vision and versioned roadmap (`docs/vision.md`), 2026-11-17

Two fresh reviewer subagents stood in for the owner: Reviewer A, a pragmatic product reviewer (Sonnet), and Reviewer B, a skeptic told to assume the plan is wrong (Opus, which checked the API claims against developer.spotify.com). Each was given the doc and the requirements, without the author's conclusions. The limit was 2 rounds.

- **Round 1, A: CHANGES (8 points).** Accepted: tighter v1.1 done-when checks; v2 not gated on a "2 weeks / 200 tracks" wait, with the seed playlist as the primary source at launch; search split from the UI redesign and shipped first; an artist-first typeahead; Recently played moved earlier (v1.2); minimal owner controls moved from v3 to v1.2; "Quiet now" shows who and until when; the licensing risk turned into a decision the owner makes before the v1.1 deploy; stats, kiosk and playlist sync moved to an "only if asked" backlog.
- **Round 1, B: CHANGES (10 points).** Accepted: the `GET /artists/{id}/albums` limit is now 10 (verified on the reference page), so Albums and Singles are separate paged lists; `end_reason` plus progress is recorded on every play, and v1.1 starts with a real-device spike whose recordings become test fixtures; a device skip counts only when a different track shows on the same device, and `lost` is kept apart; the fair-queue rule failed its own test once the order was recomputed (verified), so it became "the requester served longest ago goes next", tested by a simulation; a seed playlist minimum (100 tracks, 40 artists) and no "then idle"; device skips of auto-picks count as vetoes; v1.1 cut to what makes the log honest; deeper cuts and stats moved to the backlog; done-when checks made measurable; primary sources replaced weak ones (festify.rocks, news.ycombinator.com, Spotify quota-modes), and forum-only claims labelled unverified. Partly declined: "poll every 10 s while playing" was accepted, but the v1 lookahead timer stays, which already does the "timed check at the expected end". "Exponential back-off" was accepted with concrete numbers (1 min doubling to 30 min). These are our own choices, as Spotify publishes no numbers.
- **Round 2, A: CHANGES (5 points).** Accepted: idle silence, quota back-off and the Guided Access docs pulled into v1.1; v1.2 resized to 2–3 sessions and the ntfy alert moved to the backlog, keeping a random topic and messages without names; Quiet now always pauses and resumes the same song, with nothing logged as ended; the v2 auto-pick is chosen when the lookahead timer fires, so there is no gap between songs. Declined: moving likes out of v1.2. They are cheap, and collecting them early gives v2 scoring data.
- **Round 2, B: CHANGES (6 points).** Accepted: the same quota gap (verified: `src/spotify.js` retries a 429 without `Retry-After` after a flat 5 s), now fixed in v1.1; the v1.1 veto is tested with an `auto` item inserted by a fixture; v2 adds a wake-up at the start of office hours and a 60 s slow wake while the queue is empty, because idle polling is off; up-next shows the simulated fair order; a `lost` request goes back to the head of the queue once if it had not reached 50%; Quiet now pauses rather than lowering the volume, which settles the volume-restore and queue-draining questions.
- **Final:** both reviewers ended round 2 on **CHANGES**, and the cap of 2 rounds was reached. Every point in round 2 was applied, except the decision to keep likes in v1.2. They were not re-run a third time. No point was rejected on substance.
