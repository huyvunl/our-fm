# Reviewer verdicts

Fresh Sonnet reviewer subagents stood in for the owner at each approval point.

- **Design (brainstorm), round 1: CHANGES.** Accepted: transfer-and-retry on 404 device, least-privilege scopes, `trust proxy`, server-side OAuth state, JSON-only mutating requests, `/auth/login` only while disconnected, per-browser clientId for votes/cap/remove, pause when queue runs dry, restart reconciliation, passcode min length, no token logging. Partly declined: kept the HMAC cookie (3 lines, no extra secret); skip/cap numbers became constants rather than env vars.
- **Spec, round 1: CHANGES.** Accepted: 403 handling, vote counts only if clientId *and* normalized name are new, votes reset per play, passcode ≥ 8 chars, security headers + CSP, two consecutive misses before ending a song, 2 h no-repeat stated as auto-pick only, clientId in a header not the URL, pinned Node 24 + silenced sqlite warning. Declined: owner-id check on `/auth/login` (passcode + only-while-disconnected is enough for trusted colleagues, and avoids another owner step); per-person skip cooldown (multi-person thresholds already meet "one person can't skip everything"); dropping the lookahead timer (avoids up to 3 s silence per song; races covered by the lock + play-id check and tests); estimated progress on normal ends (the required column is progress at skip only). Not re-reviewed: all changes were additive clarifications.
- **Plan, round 1: CHANGES.** All accepted: fake-clock contract (`clock.now()` everywhere, tests drive `tick()`), a concrete race-test recipe, an explicit lock snippet that keeps the chain alive while `skip()` still rejects, `autopick` passed as `{ pick }`, a second play refusal in a row no longer drains the queue (spec updated too), middleware order with static before `requireAuth`, a DEPLOY.md content list, Windows-safe temp cleanup in the smoke test. Not re-reviewed: precise additions, no direction change.
